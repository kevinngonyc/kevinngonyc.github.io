attention scheduling.

inspector–executor vs. online scheduling for irregular batched attention.
read the proposal (pdf) →
Attention(Q, K, V) = softmax( QK⊤√dk )V

Attention is the core mechanism in transformers, and it is dominated by matrix multiplications that can run in parallel. Variable-length sequences complicate this, because standard batched attention expects uniform dimensions. The naive fix is to pad every sequence to the longest one, which spends much of the memory and compute on padding.

FlashAttention tiles the computation so the full attention-score matrix never sits in GPU memory. It handles variable lengths by packing sequences contiguously and restricting attention within each one. That removes the padding, but leaves load imbalance: tiles from long sequences take longer than tiles from short ones, so some SMs finish early and sit idle.

An inspector–executor plan precomputes a workload-aware schedule of attention tiles to improve GPU utilization. We want to see whether online methods, which assign tiles at runtime, can avoid that planning overhead while keeping attention execution time about the same.

approach.

naive baseline.

One query tile per thread block. The hardware block scheduler decides placement.

inspector–executor.

Precompute a longest-processing-time-first schedule on the CPU, then execute it on the GPU.

online.

A persistent kernel that pulls tiles dynamically at runtime, coordinating through global variables.

All three sit on top of a simplified forward-only tiled attention kernel with variable-length sequence support, modeled on FlashAttention and FlashAttention-2, with FlashInfer as the reference for inspector–executor scheduling.

goals.

~1e-3
max absolute error against PyTorch, about the magnitude of FP16 error.
5%
lower kernel latency than the naive baseline for both schedulers. FlashAttention-4's LPT ordering reports a 4–8% FLOPS gain.
