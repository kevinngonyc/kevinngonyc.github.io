attention scheduling.

inspector–executor vs. online scheduling for irregular batched attention.
read the proposal (pdf) →

summary.

We are going to develop a precomputed inspector-executor and online scheduling method for irregular batched attention on GHC NVIDIA GPUs. We will compare the approaches against a naive static scheduling baseline. Performance will be analyzed primarily on attention execution time, scheduling overhead, and speedup against the baseline.

background.

Attention(Q, K, V) = softmax( QK⊤√dk )V

Attention is the primary mechanism in transformers, which is dominated by matrix multiplications. These matrix multiplications can be executed in parallel, but variable length sequences cause issues due to standard batched attention requiring uniform dimensions. The naive approach is to pad variable length sequences to the longest sequence length. This introduces inefficiencies, as much of the memory and compute can be wasted on this padding.

FlashAttention is an optimization of attention, which uses tiling to avoid storing the entire attention-score matrix in GPU memory. It deals with variable length sequences by storing them contiguously, marking the delineation between inputs and restricting attention within each one. Solutions such as these deal with variable length attention, but problems of load imbalance remain. Tiles from longer length sequences will take longer to calculate than tiles from shorter sequences, potentially leaving some SMs idle.

An inspector-executor plan precomputes a workload-aware scheduling of attention tiles to improve GPU utilization. We want to investigate online methods where tiles are assigned at runtime, to see if we can minimize the scheduling overhead of an inspector-executor approach while maintaining similar attention execution time.

the challenge.

The primary challenge is how to distribute attention workload to minimize load imbalance across SMs, caused by tiles of sequences of varying length. Another challenge is how to best tile to maximize GPU block efficiency, which will be encountered during implementation, but is not the primary learning goal.

One difficulty of the load imbalance problem is that the scheduling overhead of a precomputed plan may be too costly.

At the same time, coordination and the lack of global awareness of online methods can lead to more GPU underutilization.

The goal is to determine when a precomputed schedule is favorable over an online schedule and how to best construct those schedules.
dependencies.
  • Between tiles, there are no dependencies because each query tile only reads key/value tiles, computing separate portions of the output.
  • Within each tile computation, there are dependencies between iterations over key/value tiles in a sequence, as online softmax requires computational results from previous iterations.
  • There is also a dependency on schedule creation for the precomputed inspector-executor approach. For the online approach, there may be dependencies with shared variables.
memory access characteristics.
  • Each thread block loads a query tile into on-chip memory once and reuses it across all key/value tile iterations.
  • Key/value tiles have spatial locality because they are stored contiguously in memory. Many query tiles access the same key/value tiles, so these key/value tiles can be stored in cache. If query tiles from the same sequence run far apart in time, it may lead to increased L2 cache misses.
  • Inspector–executor accesses a task schedule from memory. Online scheduling may use shared variables, introducing additional memory accesses and synchronization overhead.
  • There is generally a low communication to computation ratio, since there is memory reuse with query tiles and caching of key/value tiles. The attention calculation tends to be compute-bound. When tiles are small or sequences are short, however, the calculation becomes cheaper and scheduling overhead remains approximately constant, leading to an increase in communication to computation ratio.
divergent execution.
  • There is little warp divergence, since every thread in a block works on the same sequence. There may be some warp divergence for partial tiles.
  • The more significant concern comes from the varying execution times of different blocks, leading to SM underutilization.
constraints.
  • One constraint is the amount of resources on an SM. The shared memory, registers, number of threads per block, and number of blocks that can fit on an SM affect the granularity of work distribution.
  • There is also no control over the hardware scheduling of blocks to SMs. A schedule has to map tiles to blocks without assuming any mapping of blocks to hardware.
  • Each task also has to run to completion and the workload cannot be balanced after it starts. This means the computation of tiles from long sequences potentially forces other SMs to remain idle.
  • The separation of host and device memory increases latency and introduces synchronization for a precomputed inspector-executor schedule that is created on the CPU.
  • Communication bandwidth and latency across different SMs also play a factor for any global variables related to online scheduling.

resources.

We will be using NVIDIA GeForce RTX 2080s on the GHC machines. We will implement a simplified forward-only tiled attention kernel with variable-length sequence support, using FlashAttention and FlashAttention-2 as references. FlashInfer will be used as a reference to implement inspector-executor scheduling. The implementations will use CUDA C++. Profiling will be done with NVIDIA Nsight Compute and Nsight Systems. PyTorch will be used as a correctness reference. We do not anticipate needing any additional resources at this time.

platform choice.

We are using GPUs because attention is a highly parallelizable operation that maps well onto GPUs. The scheduling problem has unique GPU constraints, such as limited SM resources or hardware block scheduling, which differ from CPUs. CUDA C++ gives us direct control of the work assignment. We use the GHC machines in particular because they are easily available resources, and the general applicability of the scheduling problem does not depend on the type of GPU.
